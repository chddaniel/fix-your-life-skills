# Autopilot Interrupts

Convert a concern, anti-vision, or identity hypothesis into observations gathered during an ordinary day. The prompts should interrupt patterns, not become another productivity ritual.

## Gather context

Ask for today's rough schedule, the pattern under investigation, and any anti-vision or desired direction already defined. If none exists, ask what repeated behavior the user wants to catch.

## Design the prompts

Choose four to six moments that do not conflict with demanding or unsafe activities. Tie each question to the context likely occurring then.

Cover a useful mix of:

- what the user is avoiding;
- what an observer would infer from the last block of behavior;
- whether the current action moves toward or away from the desired life;
- what important thing is being minimized;
- where identity protection shaped a choice;
- when the user felt unusually alive or depleted.

Avoid repeated generic motivation slogans. Each prompt should be answerable in one or two sentences.

Use varied, non-conflicting times when the schedule allows it. Never place an interruption during driving, caregiving, focused meetings, or another context where responding would be unsafe or irresponsible.

## Prepare, do not silently schedule

Return suggested times and reminder-ready text. If the user asks to create reminders or calendar events, show the exact entries first and obtain any approval required by the available tool before writing externally.

## Close the loop

At the end of the day, cluster the answers into observations, competing explanations, and one pattern worth testing tomorrow. Do not treat a single day's observations as a diagnosis.

Treat ignored or repeatedly snoozed prompts as observations about timing, friction, or avoidance rather than moral failure.

## Output

- Pattern being observed
- Prompt schedule
- Capture format
- Evening synthesis questions
- One next-day experiment
